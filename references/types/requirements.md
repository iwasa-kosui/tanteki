# 要求・仕様

## 要求仕様

PdM（プロダクトマネージャー）、開発者、QA（品質保証）担当、顧客・業務担当に向けた要求書である。必要な能力、制約、優先度を明文化する。実現方式は固定しない。区分は `stock` とする。

必要な情報は次のとおりである。

- 要求
- 優先度
- 根拠
- 制約
- 検証方法

## ユーザーストーリー

PdM、開発者、QA担当に向けた利用者要求の記述である。利用者が何をしたいか、なぜ必要かを、実装可能な単位で示す。技術設計や進捗台帳にはしない。区分は `stock` とする。

必要な情報は次のとおりである。

- 利用者
- 行動
- 価値
- 受入条件

## ユースケース

業務担当、開発者、QA担当に向けた利用手順の記述である。通常の流れ、例外、関係者、結果を記述する。画面の見た目だけを定める文書にはしない。区分は `stock` とする。

必要な情報は次のとおりである。

- 操作する人や、やり取りする外部システム
- 前提
- 通常の操作の流れ
- 例外
- 結果

## 機能仕様

開発者、QA担当、PdMに向けた機能の仕様書である。入出力、状態、ルール、エラーを、実装できる詳しさで定める。アーキテクチャ判断やタスク分解は行わない。区分は `stock` とする。

必要な情報は次のとおりである。

- 入力
- 出力
- 状態
- ルール
- エラー
- 例

## 非機能要求

開発者、SRE（信頼性エンジニアリング）担当、セキュリティ担当、QA担当に向けた品質基準の仕様書である。性能、可用性、保守性、安全性の基準を定める。具体的な製品や実装を無条件には選ばない。区分は `stock` とする。

必要な情報は次のとおりである。

- 指標
- 目標値
- 測定方法
- 制約
- 例外

## API 仕様

API 利用者、開発者、QA担当に向けた外部接続の仕様書である。外部との入出力契約と互換性を定める。サーバ内部のクラス設計は説明しない。区分は `stock` とする。

必要な情報は次のとおりである。

- エンドポイント
- 型
- 認証
- エラー
- 互換性

## データ/イベント仕様

開発者、データ基盤担当、分析担当、QA担当に向けたデータ仕様書である。データの構造、各項目の意味、バージョン、保持期間を共有する。業務全体の手順や分析結果は記録しない。区分は `stock` とする。

必要な情報は次のとおりである。

- 項目
- 型
- 必須性
- 意味
- 版
- 保持期間

## 仕様書の2つの形

番号を振った章で要件を並べる形と、対象ごとに設定と方針を並べる形がある。前者は機能の要件を決める文書、後者は運用や監視の設定を確認するための文書になる。どちらを書くかを決めてから節を作る。1つの文書に混ぜない。
