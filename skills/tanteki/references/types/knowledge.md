# 知識・計画・記録

## プロジェクト計画

PM（プロジェクトマネージャー）、開発、関係部署に向けた計画書である。成果物、担当、節目、先に必要な作業・条件、リスクを調整する。要求や設計の根拠を保存する文書ではない。区分は `flow` とする。

必要な情報は次のとおりである。

- 成果物
- 担当
- 節目
- 先に必要な作業・条件
- リスク
- 判断が必要な時期・条件

## 進捗/status report

チーム、管理者、関連する作業の担当者に向けた進捗報告である。現在の状況、前回からの変化、作業を妨げている要因、判断してほしい事項を伝える。仕様・設計・決定の正式な参照先にはしない。区分は `flow` とする。

必要な情報は次のとおりである。

- 報告の対象期間
- 完了した内容
- 次に行う作業
- 作業を妨げている要因
- 誰に何を決めてほしいか

## 技術調査の報告（Spike）

開発者、PdM（プロダクトマネージャー）、意思決定者に向けた技術調査の記録である。不確実性を減らすために調べたこと、選択肢、限界を残す。意思決定や実装の進捗管理の代わりにはしない。区分は `record` とする。

必要な情報は次のとおりである。

- 問い
- 方法
- 観察
- 限界
- 提案

## 会議メモ/決定ログ

参加者、欠席者、関係者に向けた会議の記録である。論点、決定、次に行う作業を後から確認できるようにする。正式仕様や ADR の代替にはしない。区分は `record` とする。

必要な情報は次のとおりである。

- 日付
- 参加者
- 論点
- 決定
- 担当・期限

## README

利用者、開発者、保守者に向けたリポジトリやサービスの案内である。入口と次の行動を示す。完全な API 仕様や設計書を複製する文書ではない。区分は `stock` とする。

必要な情報は次のとおりである。

- 対象
- 開始手順
- 主要リンク
- 保守者

## チュートリアル

初学者や利用者に向けた導入手順である。最小の成功体験へ導く。全機能のリファレンスにはしない。区分は `stock` とする。

必要な情報は次のとおりである。

- 前提
- 手順
- 期待結果
- 次のリンク

## 操作/利用ガイド

利用者、CS（カスタマーサポート）、運用担当に向けた操作手順である。よくある目的を安全に達成する方法を示す。内部実装や開発進捗は説明しない。区分は `stock` とする。

必要な情報は次のとおりである。

- 対象
- 前提
- 手順
- 結果
- 注意
- 問い合わせ先

## FAQ/トラブルシュート

利用者、CS、オンコール担当に向けた問題解決案内である。症状から確認・解決までを短くたどれるようにする。根本原因の正式な記録や、個別の障害の経過を記録する文書としては使わない。区分は `stock` とする。

必要な情報は次のとおりである。

- 症状
- 条件
- 確認
- 解決
- 自分で解決できない場合の相談先と連絡方法

## 確認依頼

確認を依頼するときは、相手に同意してほしい内容を文で示す。観点を並べるだけでなく、何に同意するか、何を修正してほしいかを返せる形にする。
