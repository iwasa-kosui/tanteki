短く書く。

設計の理由も、失敗する条件も、例外も。

エージェント用の執筆・推敲スキルです。

01 / BEFORE & AFTER

読むと、違いがわかる。

同じ依頼から生まれた、2つの文書。
実際の出力を、全文で並べました。

「なし／あり」は同じ依頼から別々に生成した結果です。同じ文章を順に編集した履歴ではありません。2026年9月6日の保存記録から紹介します。

各欄をスクロールして全文を読めます。本文は原文のまま掲載し、比較する箇所に色を付けています。

02 / HOW IT WORKS

短くする、その前に。

01

構成を決める

読者と目的を決め、節ごとの問いと根拠を整理します。短い案内なら、一段落で止めます。

02

意味を確かめる

事実・条件・例外を原資料と照合します。提案や未決定の内容を、確定した仕様に変えません。

03

文章を検査する

文の意味の点検に加え、textlint で語法や曖昧な表現を検査します。資料の不足も明記します。

スキルの手順を読む ↗

03 / GET STARTED

次の文書で、試してみる。

使っているエージェントに追加して、
読者と目的を添えて依頼します。

1

スキルを入れる

GitHub CLI 2.90以降と
Node.js 22以降が必要です。

gh skills install iwasa-kosui/tanteki tanteki --scope user

ターミナルで実行します。文書検査の依存関係は、初回利用時にエージェントが npm ci で導入します。公式のインストール手順 ↗

2

文書を渡す

新しいセッションを開き、
依頼文と草稿を渡します。

依頼文の例
tanteki を使って、この設計書を開発者向けに短く推敲して。
実現方式と不採用案の理由、制約、例外は残して。

（ここに草稿を貼る）

新規の執筆も依頼できます。原資料と、未決定の内容を添えてください。
