文書の種類ごとに、必要な情報を検査する Skill

文書の種類ごとに、書くべき情報と書くべきではない情報が違います。

01 / BEFORE & AFTER

スキルなしと、スキルありの出力を比べる

同じ依頼から別々に生成した2つの文書を、全文で並べています。

「なし／あり」は同じ依頼から別々に生成した結果です。同じ文章を順に編集した履歴ではありません。2026年9月20日の実測から、同じ3課題の反復1を紹介します。

各欄をスクロールして全文を読めます。本文は原文のまま掲載し、比較する箇所に色を付けて、違いや共通点をその下に書き添えています。

02 / DOCUMENT TYPES

文書の種類ごとに、書くべき情報は違う

規定は種類ごとに定義されていて、依頼の内容から該当する1つを選びます。

文書の種類ごとの規定
文書の種類書くべき情報書くべきではない情報
PRD要求・優先度・根拠・制約・検証方法進捗報告・課題IDの台帳
Design Doc背景・目標と非目標・設計・代替案・影響・リスク・未解決点進捗報告・課題IDの台帳
ADR背景・決定・代替案と理由・結果・状態詳細設計・実装の進捗・作業チケットの管理
Runbook前提・検知・手順・確認・停止条件・連絡先事故の原因分析・作業の進捗
調査報告方法・対象・観察・解釈・限界・示唆一人の発言からの市場全体の断定

文書の種類は7つのカテゴリに分かれています。依頼の内容から該当する種類を1つ選び、その規定だけを読みます。

03 / HOW IT WORKS

構成を検査してから、本文を書く

01

文書の種類と読者を決める

文書の種類を決めると、読者と、その種類で書くべき情報が決まります。節ごとの問いと根拠を整理します。

02

構成を検査する

構成が合格するまで本文を書きません。検査していない構成を、合格済みとして扱いません。

03

本文を検査する

事実・条件・例外を原資料と照合し、textlint も通します。原資料にない事実や数値は書きません。

構成と本文のそれぞれで、初稿・修正・能力帯の昇格の3回までを上限とし、1つの文書で最大6回に収めます。満たせなければ、残る問題を明記して草稿として返します。

05 / EVIDENCE

評価の結果と、生成した文書の全文

2026年9月20日、10課題を各2回、スキルなし／ありで生成しました。両条件とも、文章検査の指摘による修正は最大1回です。

対象は実行時の main ca1c0eb。生成は gpt-5.6-luna / low、5基準の採点は gpt-5.6-terra / low、用途のレビューは gpt-6-astra / high です。

比較するのは執筆指示の付与効果です。構成検査や委譲を含む通常の工程全体は測っていません。作成者が選んだ10課題と単一モデルの判定による小規模な比較であり、PRD は含みません。

固定した5基準の採点と生成量
指標なしあり

5基準は事実・根拠・役割・明確さ・簡潔さです。LLM の生の採点には誤判定があり、短さや文章検査の合格だけでは品質を判断できません。

トークンは生成と修正の合計で、入力はキャッシュを含みます。採点・レビューの利用量は含みません。
