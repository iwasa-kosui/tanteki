# 比較条件の修正と入力の検証

旧方式の「スキルなし」側にもスキルが適用されているとの指摘を受け、保存した出力と実行コードを確認した。2026年9月20日の20件のうち8件に lint の指摘を返し、そのうち6件に `stock-boundary` などの独自ルールが含まれていた。9月6日にも、7件の修正のうち6件で独自ルールを返していた。両日の旧実行を [無効化の一覧](invalidated-runs.json) に登録した。

修正後は、スキルなし側には初稿1回だけを生成させる。lint は生成後の測定に使い、モデルへ指摘や改稿指示を返さない。スキルあり側には執筆指示と関連資料を渡し、lint に応じた修正を最大1回返す。両条件は同じ課題・モデル・推論量を使う。この比較の対象は、執筆指示と lint 修正を合わせた効果であり、委譲や構成検査を含む通常の工程全体ではない。

CLI のスキル無効化を指定するだけでなく、保存セッションの入力を各呼び出しで検査する方式に変えた。新規1ターンであること、指定モデル・推論量・基本指示・原依頼との一致を確認する。共通の AGENTS.md 指示とモデル固有の操作指示は [固定した入力のハッシュ](runtime-context.json) と照合する。一時パスと日付だけを正規化し、スキル一覧など想定外の指示があれば拒否する。ツールの使用も拒否する。

生成モデルの入力を確認した予備実行では40原文を生成したが、採点・レビュー用モデルに追加される共通指示を入力検査が拒否した。スキルの記載ではなく、モデルごとの操作・委譲に関する共通指示であることを確認し、モデル別に固定した。予備実行はローカルの診断記録として保持し、公表する比較値には含めない。固定後の条件で全件を新たに生成・評価する。

公開用のビルドでは、各呼び出しの入力ハッシュを確認し、保存した課題・スキル資料から依頼文を再構成して照合する。スキルなし側の追加呼び出し、セッションの使い回し、原文と掲載本文の差がある場合はビルドを失敗させる。共通指示のハッシュ、モデルへ渡した依頼文、両条件の原文を検証用に保存する。共通の操作指示そのものはローカルの診断記録に保持し、公開データには含めない。新しい実行の結果は [測定メモ](results/2026-09-20-isolated-ca1c0eb/run-notes.md) を参照する。
