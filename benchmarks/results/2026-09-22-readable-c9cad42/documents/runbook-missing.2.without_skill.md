# 本番キャッシュ再起動手順（ドラフト）

## 重要
現在確定している資料は「監視でエラーを見たらキャッシュを再起動する」のみです。以下は未確定項目を明示したドラフトであり、このまま本番作業には使用しないでください。

## 1. 再起動の判断
1. 監視でキャッシュに関するエラーを確認する。
2. エラーの対象サービス・環境・発生時刻・影響範囲を記録する。
3. 次の項目が確定するまで作業を開始しない。
   - 対象ホスト／サービス
   - 再起動コマンド
   - 停止してよい条件
   - 事前確認・承認者
   - 連絡先およびエスカレーション先

## 2. 事前確認
以下を確認し、記録する。

- 対象が本番環境であること
- 対象キャッシュのホスト名・サービス名
- 現在のエラー内容と影響範囲
- 再起動による影響（キャッシュ消失、遅延、接続断など）
- 作業を停止してよい条件
- 関係者への事前連絡要否

※確認方法および連絡先は未決定。

## 3. 再起動
1. 定められた承認者から実施許可を得る。
2. 関係者へ作業開始を連絡する。
3. 対象を再確認する。
4. 承認済みの再起動コマンドを実行する。

**再起動コマンド：未決定（要記載）**

実行時刻、実行者、対象、コマンド、結果を記録する。

## 4. 復旧確認
再起動後、以下を確認する。

- キャッシュサービスが稼働している
- 監視エラーが解消している
- アプリケーションのエラーが解消している
- キャッシュへの接続が正常である
- 必要な場合、代表的な業務処理が成功する
- 再起動による異常（負荷上昇、接続エラー、性能劣化）がない

**具体的な確認コマンド・監視画面・正常判定基準：未決定（要記載）**

## 5. 復旧しない場合
1. 再起動を繰り返さない。
2. 実施内容、発生時刻、エラー、ログを記録する。
3. 定められた連絡先へエスカレーションする。

**連絡先・エスカレーション先：未決定（要記載）**
