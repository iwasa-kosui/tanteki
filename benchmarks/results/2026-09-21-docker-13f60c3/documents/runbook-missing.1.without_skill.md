# 本番キャッシュ再起動手順（ドラフト）

> **注意:** 本手順は未確定事項を含むドラフトです。再起動コマンド、実施条件、復旧確認方法、連絡先が確定するまで、本番環境で実施しないでください。

## 1. 対象
- 対象サービス: **[キャッシュサービス名]**
- 対象環境: **本番環境**
- 実施者: **当番担当者**

## 2. 実施判断
監視でエラーを検知した場合、まず以下を確認する。

1. エラーが継続しているか
2. 影響範囲と影響度
3. キャッシュ再起動が原因として妥当か
4. 再起動による影響（キャッシュ消失、負荷増加、可用性低下など）
5. 他の担当者による対応が進行中でないか

### 再起動してよい条件
以下をすべて満たす場合のみ、再起動を実施する。

- **[停止してよい具体的な条件]**
- **[再起動対象インスタンス／ノードの特定が完了している]**
- **[再起動による影響を確認済み]**
- **[必要な承認者の承認を取得済み]**
- **[連絡先への通知またはエスカレーションを実施済み]**

条件を満たさない場合、または判断に迷う場合は、再起動せず **[連絡先／エスカレーション先]** に相談する。

## 3. 事前確認
- 監視エラーの発生時刻と内容を記録する。
- 対象サービスと対象ノードを確認する。
- アプリケーション、ネットワーク、データベースなど周辺障害の有無を確認する。
- 作業開始を **[連絡先／チャネル]** に連絡する。
- 必要に応じて作業記録を開始する。

## 4. 再起動手順

1. **[再起動コマンド]** を実行する。
2. コマンドの実行結果を確認し、開始時刻と実行者を記録する。
3. 停止完了を確認する。
4. 起動完了を確認する。
5. 起動後のエラーやログを確認する。

> **未確定:** 再起動コマンド、実行ユーザー、接続先、停止・起動の個別手順は、運用責任者が確定すること。

## 5. 復旧確認
以下をすべて確認する。

- キャッシュサービスが稼働状態である。
- **[ヘルスチェックコマンドまたは確認URL]** が正常である。
- 監視エラーが解消している。
- アプリケーションからのアクセスが正常である。
- エラーログやリソース使用率に異常がない。
- 必要に応じて、キャッシュヒット率やバックエンド負荷が通常範囲に戻っている。

復旧しない場合は、追加の再起動を繰り返さず、**[連絡先／エスカレーション先]** に連絡する。

## 6. 事後連絡・記録
以下を記録し、**[連絡先／作業記録システム]** に共有する。

- 監視エラーの内容と発生時刻
- 再起動の判断理由
- 対象サービス・ノード
- 実施者、開始時刻、終了時刻
- 実行したコマンド
- 復旧確認結果
- 残存する問題や追加対応

復旧後、**[連絡先／チャネル]** に完了報告を行う。

## 7. 確定が必要な項目
- キャッシュサービス名と対象ノード
- 再起動コマンド
- 停止してよい具体的な条件
- 承認者とエスカレーション基準
- ヘルスチェック方法
- 監視で確認する項目
- 連絡先、連絡手段、連絡のタイミング
- 復旧しない場合の次の対応
