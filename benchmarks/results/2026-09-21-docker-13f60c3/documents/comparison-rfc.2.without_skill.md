# RFC: 商品検索基盤の方式選定

- **関連**: SEARCH-88 / PR #71
- **レビュー期限**: 8月28日（要更新）
- **提案**: 方式B（検索専用サービス）

## 1. 背景・問題
商品検索が遅く、特に部分一致検索の応答性能が課題になっている。計測値・費用見積もりは現時点で未取得である。

## 2. 選択肢

| 方式 | メリット | デメリット |
|---|---|---|
| **A: 既存DB索引の追加** | 新たな運用対象が増えない | 部分一致検索は高速化しない |
| **B: 検索専用サービス** | 部分一致検索の高速化が期待できる | 別サービスの運用が必要。DBからの反映に遅延が生じる |

## 3. 提案
方式Bを採用し、商品検索を検索専用サービスへ切り出す。検索インデックスはDBから連携して更新する。

検索結果は最大60秒古くなる可能性を許容する。ただし、この許容については業務側の承認が未取得であり、採用条件とする。

## 4. 合意が必要な事項
1. 検索専用サービスを追加し、継続運用すること
2. DB更新から検索結果への反映遅延を最大60秒許容すること

## 5. 未確定事項・確認事項
- 方式Bの性能改善効果を計測する
- 運用費用・導入費用を見積もる
- 連携失敗時の再試行・監視・復旧方針を定める
- 業務側から「最大60秒の検索結果の古さ」について承認を得る

## 6. 決定依頼
開発チームには、上記2事項について合意可否を判断してもらいたい。特に、業務側の承認なしに60秒の許容を確定しない。
