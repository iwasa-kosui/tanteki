# 本番キャッシュ再起動手順（ドラフト）

## 1. 目的
監視でキャッシュに関するエラーを検知した場合に、当番が安全に状況を確認し、必要に応じて再起動するための手順です。

> **重要：本手順は未完成です。** 再起動コマンド、停止してよい条件、復旧確認方法、連絡先が未確定のため、現時点では本番環境で再起動を実施しないでください。

## 2. 監視でエラーを検知したら
1. アラートの発生時刻、対象サービス、対象ホストまたはクラスタ、エラー内容を記録する。
2. 同じ時間帯に、アプリケーション、データベース、ネットワークなどの障害が発生していないか確認する。
3. キャッシュの再起動が必要かどうかを判断する。
4. 判断に必要な情報が不足している場合、自己判断で再起動せず、所定の連絡先へ相談する。

## 3. 再起動前の確認
以下をすべて確認できるまで、キャッシュを停止しない。

- [ ] 対象環境が本番環境であることを確認した
- [ ] 対象のキャッシュサービス／インスタンスを特定した
- [ ] 再起動による影響範囲を確認した
- [ ] 停止してよい条件を満たしている
- [ ] 実施予定と影響を関係者へ連絡した
- [ ] 必要な承認を取得した
- [ ] 再起動前のメトリクス、ログ、アラート状態を記録した

## 4. 再起動を実施してよい条件
この条件は未決定です。運用責任者が以下を確定してください。

- 再起動対象となるエラーの種類・継続時間・発生回数
- 再起動を禁止する時間帯やリリース中の扱い
- 再起動してはいけない状況（データ障害、ネットワーク障害、依存サービス障害など）
- 再起動前に必要な承認者
- 再起動回数や再試行回数の上限

条件を満たさない場合、または判断できない場合は再起動せず、エスカレーションする。

## 5. 再起動手順
1. 実施者、実施時刻、対象、実施理由を作業記録に残す。
2. 関係者へ作業開始を連絡する。
3. **承認済みの本番用再起動コマンドを実行する。**
   - コマンド：`未確定（要記入）`
   - 実行対象：`未確定（要記入）`
   - 実行ユーザー／権限：`未確定（要記入）`
4. 停止・再起動中のログとメトリクスを確認する。
5. エラーが継続する場合は、定められた上限を超えて再起動を繰り返さず、エスカレーションする。

## 6. 復旧確認
復旧確認方法は未決定です。少なくとも以下を確認できる手順を定義してください。

- キャッシュサービスが稼働状態である
- ヘルスチェックが成功している
- 監視アラートが解消している
- アプリケーションからのキャッシュアクセスが成功している
- エラー率、レイテンシ、接続数などが通常状態へ戻っている
- 必要に応じて代表的な業務処理が成功している

確認コマンド・URL・正常値：`未確定（要記入）`

## 7. 復旧しない場合
1. 再起動を繰り返さない。
2. 発生時刻、対象、実行した操作、ログ、メトリクス、現在の影響を記録する。
3. 定められた障害対応窓口へ連絡する。
4. 連絡先が未確定の場合は、当番責任者またはサービス所有者を確認して連絡する。
5. 影響が継続している場合は、関係者への状況共有を継続する。
